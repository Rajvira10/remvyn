# Remvyn — naming and identity

Research date: **24 October 2026**. Product brief verified against the repository's `README.md`. This is a design proposal; no application names, code, repository names, domains, accounts, or releases were changed.

## Recommendation

**Remvyn**, pronounced **REM-vin**. Six letters, two syllables, with a useful suggestion of “remote” and enough breadth for SSH, files, encrypted vault sync, and server visibility. The spelling is coined; it does not have an established dictionary meaning. Use **Remvyn** in prose and the supplied lowercase lettering in the logo. Suggested descriptive line: **SSH access. Servers in view.**

Remvyn has the cleanest observed results in this screen: no named software product identified in the target domain; zero GitHub repository-name results; no exact GitHub account or npm package returned; zero US Apple software-search results; no TMview contains-search rows; and not-found responses for all four requested domains. These are dated observations, not a guarantee of availability or legal clearance.

The principal tradeoff is spelling from speech: “Remvin” is a plausible transcription. A targeted phonetic-spelling web search found unrelated businesses and incidental text, with no relevant tool identified. Similar-sounding marks and international-language meanings have not been comprehensively cleared. [Remmina](https://remmina.org/) is an established remote desktop client; the shared “Rem” prefix is a residual similarity consideration, even though the names differ in spelling, syllables, and ending.

## Logo and palette

The **paired-route** symbol uses two opposing open channels with rounded bends and square terminals. Their rotational symmetry suggests traffic moving both ways through the same connection, with deliberate negative space between the routes. It hints at SSH, forwarding, and sync without a prompt, padlock, bolt, waveform, or tiny literal server illustration. Its silhouette can also be read as two interlocking links; it is an abstract connection symbol, not an R monogram.

The wordmark uses **original, hand-authored closed vector letter outlines**. No installed font is required, no raster is embedded, and nothing was traced. The primary symbol is two filled Bézier paths; all logo SVGs are editable vector artwork. Raster generation was unnecessary for concept exploration because the design was developed directly as vector geometry.

## Usage and implementation notes

- `mark.svg`: transparent 1024 × 1024 symbol master; use for favicons, navigation and monochrome/menu-bar derivations. Keep its aspect ratio and existing padding. Recolor all filled paths together for a white or black template icon. Native macOS template behavior must be set by the future application integration; an SVG alone does not enable it.
- `app-icon.svg`: 1024 × 1024 canvas with an inset macOS-style rounded tile, transparent outer corners and a solid dark surface. No text, glow or raster effects. Export `.icns` and Windows/Linux sizes during later integration; this task does not change the Wails build assets.
- `android-foreground.svg`: **108 × 108** transparent layer. Actual artwork bounds are **29..79dp** on both axes. The maximum control-point hull radius is **32.016dp**, inside the centered **33dp radius / 66dp diameter** safe circle. This is stricter than fitting only a 66dp square. Supply background **#15161A**, also recorded in `android-background.txt`. Do not apply the desktop rounded-square mask to this foreground. Convert to Android VectorDrawable or a build-time raster later; this SVG is a design source, not an Android XML resource.
- `wordmark.svg`: horizontal lockup, **1100 × 300**, transparent, light lettering. Keep the complete symbol/name relationship. Suggested minimum display width **160 CSS px**; use the symbol alone below that. Leave at least one channel thickness of clear space around standalone artwork outside its intrinsic canvas.
- `alt-mark.svg`: quick **Velqin** route-V concept with a live endpoint. Secondary exploration only; not a fully developed second brand system.
- Use the supplied solid mark at **16px and above**. Do not add thin internal details, gradients, bevels, status colors, or text inside the app icon. A real alert indicator should sit outside the brand symbol.

## Rendering and verification

Rendered **from the SVG sources** using `@resvg/resvg-js` 2.6.2: desktop 1024px, primary mark 16/24/32px, and alternative mark 32px. The PNGs were opened directly, and the HTML presentation was visually inspected at 728px and 360px widths, including actual-size and enlarged pixel samples. The two channel ends and central negative space remain distinguishable at 16px. The 16px render is sparse by design; no small status dot is required to recognize it.

All five SVGs parsed successfully and contain **no `<image>` or `<text>` elements**. Android control-point hull geometry was checked against the 66dp safe circle. The self-contained preview contains circle and rounded-square Android masks, a wordmark lockup, a palette, and small-size raster specimens. No application tests were needed because only standalone design artifacts were created.

To reproduce the PNGs and presentation, from the repository root:

```sh
npm install --prefix branding/.tools --cache branding/.npm-cache --no-audit --no-fund @resvg/resvg-js
node branding/generate.cjs
```

Temporary renderer dependencies and npm cache were removed after rendering. Re-running the commands recreates them inside `branding/` only. The generator is the source of truth for the SVG geometry and preview; edit it before regenerating.

## Remaining uncertainty

- A no-result search is not proof of global name exclusivity. Private repositories, unindexed launches, local stores, unregistered rights, translation/transliteration and similar-sounding brands can be missed.
- Direct USPTO search was unavailable. TMview is EUIPO-maintained but is not an official legal register; participating-office data and update coverage can vary. No blanket US/EU legal clearance is claimed.
